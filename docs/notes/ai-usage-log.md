# AI usage log

One line per occurrence: what the AI got wrong or nearly got wrong, how it was caught, the fix. Feeds `AI_USAGE.md`.

- 2026-11-06 Phase 0: initial read of the MCP SDK v2 package took the `LATEST_PROTOCOL_VERSION = '2025-11-25'` constant to mean v2 lacked the 2026-07-28 spec. Caught by checking the published package for `server/discover` and `input_required` (present); the constant only tracks the legacy handshake. Fix: record SDK capabilities from package contents, not a single constant or the README.
- 2026-11-06 Scaffold: CI workflow written with `actions/checkout@v5` / `actions/setup-node@v5` from memory; latest releases are v7.0.1 / v7.1.0. Caught by checking the GitHub releases API before committing. Fix: bumped to v7. Pattern: versions written from memory are stale; check the registry.
- 2026-11-06 Gate 1 review: ADR-0003 set a 5-minute entitlement poll and claimed data "up to 5 minutes old". That confused poll interval with data age: a nightly export is up to a day old whatever the poll rate. The 24h staleness limit would also have tripped daily before each export. Caught in human review of the ADR. Fix: 15-minute conditional polling, staleness measured from the CSV export timestamp with a 48h limit, and per-field `asOf` (ARR included).
- 2026-11-06 Gate 1 review: ADR-0004 considered iPaaS only as a consumer and as bulk ingestion; it missed iPaaS as the connectivity layer in front of the upstreams. Caught in human review. Fix: added it as a rejected alternative for request-path calls, with a revisit trigger.
- 2026-11-06 PR #1 review: the build-slice skill mapped tiers to models by example only, with no rule for unlisted work. Caught by a human PR comment. Fix: classify by what a defect would cause, round up when unsure, and record the reason in the slice table.
- 2026-11-06 Gate 2a: proposed `code` and `retryable` extensions on problem responses and HMAC-signed cursors. The human asked for standard practice; neither is needed (`type` + `Retry-After` cover the first; per-request authorization makes signing pointless). Dropped. Pattern: invented conventions where a standard already exists.
- 2026-11-06 PR 3 build: dispatched three parallel slices with worktree isolation, assuming worktrees branch from the current feature branch. They branch from the default branch, so all three started without the base commits. Caught by the base-commit check written into each slice prompt; each stopped before writing code. Fix: reset each worktree to the feature branch; the build-slice skill now requires that step.
- 2026-11-06 PR 3 build: after the reset instruction, the resumed slices ran in the main checkout, not their worktrees. Two committed straight onto the feature branch, one made its own worktree. No conflict, because each owned separate files, but the isolation assumption was wrong. Caught by checking `git worktree list` and the log before integrating. Fix: the build-slice skill now covers resumed slices.
- 2026-11-06 PR 3 review: the clock rule missed `Date()` (no `new`) and `globalThis.Date.now()`. Caught by the human asking for an explanation, which prompted another sabotage check. Fix: two more ESLint selectors; all four forms are now flagged.
- 2026-11-06 PR 4a: the first phone-number mask also matched ISO dates. Caught by a false-positive test written alongside it. Fix: skip dates and bare digit runs.
- 2026-11-06 PR 4a: the fresh-context review found four critical defects in code that passed all 112 tests: correlation IDs corrupted by the phone mask, an HTML stack-trace page for undeclared statuses, 500s for malformed JSON, and personal data in error stacks. All fixed, each with a test confirmed to fail on the old code. Our own checks missed them because the same author wrote code and tests, so they shared its blind spots. Details, per defect: [fresh-review-pr-4a.md](fresh-review-pr-4a.md).
- 2026-11-06 PR 4a: Vitest collected test files from the slice worktrees under `.claude/`, inflating the count to 192. Noticed from the number. Fix: excluded `.claude/` from Vitest, ESLint and Prettier.
- 2026-11-06 PR 4b: the fresh-context review found one critical defect in code that passed all 194 tests: rate limits were charged after request validation, so invalid and forbidden requests from authenticated callers were free and unlabelled. Also three untested failure paths (JWKS errors, missing `exp`, malformed `act`) and a long-outage weakness. Fixed with tests, each checked against the defect. Details: [fresh-review-pr-4b.md](fresh-review-pr-4b.md).
- 2026-11-07 PR 5a build: a slice's file-writing turned two `﻿` escapes in the CSV parser into literal invisible byte-order marks. Caught by ESLint (`no-irregular-whitespace`). Fix: build the character with `String.fromCharCode(0xfeff)`.
- 2026-11-07 PR 5a plan: the plan assumed cockatiel's breaker could run on the injected clock; checking the installed source showed it reads `Date.now()` and hides when it opened. Caught by the pre-build library check. Fix (human decision): keep the library, test with fake timers, report the full half-open delay as `Retry-After`.
- 2026-11-07 PR 5a: the fresh-context review found no critical defects but three majors in code that passed all 381 tests: start-up blocked on the ERP (against the spec), upstream body fragments could reach logs through a parse error's cause, and no test proved retries back off. All fixed, each with a test confirmed to fail on the old code. Details: [fresh-review-pr-5a.md](fresh-review-pr-5a.md).
- 2026-11-07 PR 5b: my shared query helper assumed the validator hands back raw query strings (from a misreading of its source); it coerces integers to numbers. `queryInt` then read `renewalWithinDays` and `limit` as absent, which silently widened the search. Caught by a slice's entitlement-stale test the first time it ran. Fix: the helpers accept coerced values and throw on a wrong type instead of reading it as absent.
- 2026-11-07 PR 5b: the fresh-context review found no critical defects, one major (the 500-account guard was untested at the handler) and five minors (provenance that claimed reads which didn't happen, untested paths). Fixed with tests confirmed to fail on the old code. Details: [fresh-review-pr-5b.md](fresh-review-pr-5b.md).
- 2026-11-07 PR 5b: building the read endpoints showed the contract's own Copilot example query fails validation when sent as written (raw colons; OpenAPI's default `allowReserved: false`). Caught by a slice's end-to-end test and confirmed on `make run`. Fix (human decision): a separate contract PR allowing reserved characters in the two timestamp parameters.
- 2026-11-07 PR 6 build: three of the slices' own sabotage checks first passed every test. Re-serialising the webhook body changed nothing because enqueue stores compact JSON; a 410 test passed because its queued row was never due (a timestamp-format mismatch in a text comparison); check-then-insert wasn't caught because the claim is synchronous in one process. Caught by running the sabotage checks. Fix: a hand-stored payload test, a control step in the 410 test, and a two-thread race test on one database file.
- 2026-11-07 PR 6: the fresh-context review found no critical or major defects; seven minors, four fixed (a store error after a successful create returned 500 and left the key in flight). Details: [fresh-review-pr-6.md](fresh-review-pr-6.md).
- 2026-11-07 PR 15: guessed the 403 problem type as `forbidden` in the Postman assertions (the contract's type is `insufficient-scope`). Caught by the first Newman run. Fix: assert the contract's type.
- 2026-11-07 Part C escalate: the fresh-context review found no critical defects and five majors. The audit-and-event transaction and the write-time 412 race had no test that could fail; a 2xx without a usable ETag turned a successful write into a 502; refusals made before the handler weren't audited, though the spec said they would be; a failed audit or event write is swallowed after the upstream accepted. Fixed with tests sabotage-checked to fail, an ETag re-read and a spec correction; the swallowed write stays (the case is already escalated) and is documented until the outbox exists.
- 2026-11-07 Part C escalate: `escalatedAt` came back with milliseconds while the rest of the API uses second precision. Caught by the end-to-end test. Fix: trim to seconds.
